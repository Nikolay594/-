# Курсовой проект

## Реализация программы контроля облачной инфраструктуры

### 1. Назначение программы

Программа предназначена для анализа телеметрических данных компонентов облачной инфраструктуры.

Программа должна считывать последовательность измерений, анализировать изменение значений компонентов, определять их состояние и обнаруживать инциденты по заданному условию.

Проект разрабатывается на языке C.

---

### 2. Индивидуальный вариант № 17 
Компоненты: API, GPU, WEB 

Порядок записи: Б — значение–время–компонент. Разделитель: запятая. 

Тип последовательности (5): Есть записи с неизвестными кодами 
компонентов; их нужно распознать и пропустить. 

Телеметрия за пять отсчётов — одна строка: 
31.3,2,WEB,43.7,1,API,50.6,4,API,34.5,5,WEB,44.2,2,API,55.2,3,GPU,51.1,5,A
PI,53.8,1,GPU,30.6,3,WEB,78.0,5,XYZ,57.2,2,GPU,51.2,5,GPU,75.0,2,XYZ,53.
2,4,GPU,32.0,1,WEB,35.2,4,WEB,44.7,3,API 

Производный показатель Q: Абсолютное изменение. 

$$Формула: Q[i] = X[i] − X[i−k]; k = 2; L = 1.0; D = 10.$$

Правило состояния компонента — Сравнение с критерием L: 

Q < −L: «СНИЖЕНИЕ»; 

−L ≤ Q ≤ L: «НОРМА»; 

Q > L: «РОСТ». 

Правило инцидента — Хотя бы одна тревога: Инцидент возникает, если 
хотя бы один компонент находится в состоянии «ТРЕВОГА» или 
«АНОМАЛИЯ». 

Структура Incident: 
typedef struct { int time; int type; float value; } Incident; 

Поля: номер отсчёта, тип инцидента, значение показателя. 

Проверь: вручную рассчитай Q для доступных пар, определи состояния 
компонентов и запиши булево выражение инцидента.

## 3. Описание инфраструктурных компонентов

| Код | Компонент |
|---|---|
| `API` | интерфейс программирования приложений (API-шлюз) |
| `GPU` | графический вычислительный ускоритель |
| `WEB` | веб-сервер |

Неизвестные коды (в данных варианта — `XYZ`) не являются контролируемыми компонентами и пропускаются.

## 4. Формат исходных данных

Каждая запись: `значение,время,компонент`, записи разделены запятой, всё записано одной строкой:

```
31.3,2,WEB,43.7,1,API,50.6,4,API,34.5,5,WEB,44.2,2,API,55.2,3,GPU,51.1,5,API,53.8,1,GPU,30.6,3,WEB,78.0,5,XYZ,57.2,2,GPU,51.2,5,GPU,75.0,2,XYZ,53.2,4,GPU,32.0,1,WEB,35.2,4,WEB,44.7,3,API
```

Порядок записей произвольный. Записи `78.0,5,XYZ` и `75.0,2,XYZ` содержат неизвестный код и исключаются. После разбора получаются три временных ряда:

| t | API | GPU | WEB |
|:-:|:---:|:---:|:---:|
| 1 | 43.7 | 53.8 | 32.0 |
| 2 | 44.2 | 57.2 | 31.3 |
| 3 | 44.7 | 55.2 | 30.6 |
| 4 | 50.6 | 53.2 | 35.2 |
| 5 | 51.1 | 51.2 | 34.5 |

На этапе КТ1 эти значения заданы в программе массивом; чтение из файла будет реализовано на КТ3.

## 5. Алгоритм работы программы (КТ1)

1. Задать три временных ряда по пять значений.
2. Для каждого компонента и каждого отсчёта `i` вычислить `Q[i] = X[i] − X[i−k]`; если `i < k`, значение не определено.
3. По `Q` и критерию `L` определить состояние компонента (СНИЖЕНИЕ / НОРМА / РОСТ).
4. Для каждого отсчёта, где состояния определены у всех компонентов, проверить правило инцидента и при выполнении записать `Incident` в массив.
5. Вывести таблицы и журнал инцидентов, сверить результат с ручным расчётом.

Функции программы: `calc_abs_change` (расчёт Q), `classify_state` (состояние), `analyze_component` (анализ ряда), `detect_incident` (правило инцидента для одного отсчёта), `find_incidents` (массив инцидентов), `verify_with_manual` (сверка с ручным расчётом).

## 6. Ручной расчёт

Период сравнения `k = 2`, критерий `L = 1.0`. Показатель определён для отсчётов 3, 4, 5.

**API**

| t | Расчёт | Q | Состояние |
|:-:|---|:-:|---|
| 3 | 44.7 − 43.7 | 1.0 | НОРМА (\|Q\| ≤ L, граничный случай) |
| 4 | 50.6 − 44.2 | 6.4 | РОСТ |
| 5 | 51.1 − 44.7 | 6.4 | РОСТ |

**GPU**

| t | Расчёт | Q | Состояние |
|:-:|---|:-:|---|
| 3 | 55.2 − 53.8 | 1.4 | РОСТ |
| 4 | 53.2 − 57.2 | −4.0 | СНИЖЕНИЕ |
| 5 | 51.2 − 55.2 | −4.0 | СНИЖЕНИЕ |

**WEB**

| t | Расчёт | Q | Состояние |
|:-:|---|:-:|---|
| 3 | 30.6 − 32.0 | −1.4 | СНИЖЕНИЕ |
| 4 | 35.2 − 31.3 | 3.9 | РОСТ |
| 5 | 34.5 − 30.6 | 3.9 | РОСТ |

**Применение правила инцидента**

| t | $S_{API}$ | $S_{GPU}$ | $S_{WEB}$ | $(S_{API}\ne0)\lor(S_{GPU}\ne0)\lor(S_{WEB}\ne0)$ | Инцидент | type | value |
|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| 1 | — | — | — | нет данных | нет | — | — |
| 2 | — | — | — | нет данных | нет | — | — |
| 3 | 0 | 1 | −1 | 0 ∨ 1 ∨ 1 = 1 | **да** | 2 | 1.4 |
| 4 | 1 | −1 | 1 | 1 ∨ 1 ∨ 1 = 1 | **да** | 3 | 6.4 |
| 5 | 1 | −1 | 1 | 1 ∨ 1 ∨ 1 = 1 | **да** | 3 | 6.4 |

Ожидаемый результат: три инцидента — в отсчётах 3, 4 и 5.

## 7. Организация данных

- `double data[3][5]` — временные ряды компонентов (строка — компонент, столбец — отсчёт);
- `ComponentResult` — для компонента хранит массив `q[5]` и массив состояний `state[5]`;
- `State` — перечисление: `STATE_UNDEFINED`, `STATE_DECREASE`, `STATE_NORM`, `STATE_GROWTH`;
- `Incident incidents[]` — журнал инцидентов.

Индексы в программе идут с нуля, номер отсчёта = индекс + 1.

## 8. Контрольный пример

Компонент `API`, отсчёт 4:

| Исходные данные | Расчёт | Ожидаемый результат |
|---|---|---|
| X[i] = 50.6 | Q = X[i] − X[i−k] = 50.6 − 44.2 | Q = 6.4 |
| X[i−k] = 44.2 (k = 2) | Q > L (6.4 > 1.0) | состояние «РОСТ» |

## 10. Сравнение с ручным расчётом

Значения `Q`, состояния компонентов и журнал инцидентов, полученные программой, совпадают с ручным расчётом из раздела 6 (во всех 9 парах `Q`, 9 состояниях и 3 инцидентах). Совпадение проверяется автоматически функцией `verify_with_manual`.

Особый случай: `API`, отсчёт 3, `Q = 1.0 = L`. По правилу `|Q| ≤ L` это «НОРМА». Чтобы ошибки округления вещественных чисел не меняли результат на границе, в сравнении с `L` используется допуск `EPS = 1e-9`.

## 11. Сборка и запуск

1. Visual Studio → *Создать проект* → **Пустой проект** (C++), добавить файл `main.c` (расширение именно `.c`, чтобы файл компилировался как C).
2. Свойства проекта → *C/C++* → *Командная строка* → добавить `/utf-8` (для корректной кириллицы в строках).
3. Сохранить `main.c` в кодировке UTF-8 (с сигнатурой).
4. Собрать и запустить: `Ctrl+F5`.
